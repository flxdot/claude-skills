# Python

The project's own rules and tool configuration take precedence where they differ.

## Tooling

- **Package manager:** `uv`. Use `uv add`, `uv remove` and `uv run`, never `pip`, `pip-tools` or `poetry`.
- **Linter and formatter:** Ruff, with a line length of 88 and LF line endings. Imports go in this order: standard library, third party, the organization's shared libraries as a separate section, then first party.
- **Type checker:** mypy, with the `sqlalchemy` and `pydantic` plugins enabled.
- **Test runner:** pytest, with `asyncio_mode = "auto"`. Test files end in `_test.py`, such as `job_service_test.py`; they do not start with `test_`.

## Code requirements

- **Type annotations.** All code is annotated, in the Python 3.10+ style: `X | Y`, not `Optional[X]` or `Union[X, Y]`.
- **Keyword arguments.** Call functions with keyword arguments.
- **Async I/O.** Functions that do I/O are async.
- **Test coverage.** All code is covered by tests. Trivial branches, such as an early return for `None` or an empty list, may stay untested; mark them with `# pragma: no cover`.

## Naming

- Variables and functions: `snake_case`.
- Classes: `PascalCase`.
- Constants: `UPPER_SNAKE_CASE`.
- Booleans start with `is_`, `has_` or `does_`, such as `is_active` or `has_permission`.
- Private members start with `_`, such as `_internal_value`.
- Dictionaries are named `<key>_to_<value>`, such as `data_id_to_asset_id`, never `<value>_by_<key>`.

## Pydantic

- **Base class.** Derive every model from the project's shared base model, so that shared configuration applies everywhere.
- **Internal transfer objects.** Between trusted internal sources, frozen dataclasses can be used instead, because they are faster.

## FastAPI

- **Function names.** Endpoint functions end in `_route`.
- **Return types.** Document the return type with a type annotation, not with `response_model` on the decorator.
- **Status codes.** Annotate every status code an endpoint can return.
- **Routers.** Register new routers through the application's plugin or factory pattern, not directly in `main.py`.

## SQLAlchemy

Write queries in Core mode, never in ORM mode.

Every ORM model class:

- is decorated with `@dataclass`;
- has a class docstring, which is reused as the table comment;
- defines `__tablename__`, and `__table_args__` with at least `"schema"` and `"comment"`;
- uses `Mapped[<type>]` with `mapped_column(...)` for every column, never the old `Column(...)` style;
- uses `Mapped[str | None]` for nullable columns, not `Optional[str]`;
- passes `comment=` to every `mapped_column(...)` to describe what the column is for;
- uses explicit SQLAlchemy column types, never Python types: `TEXT()`, `INTEGER()`, `SMALLINT()`, `BIGINT()`, `BOOLEAN()`, `TIMESTAMP(timezone=True)`, `NUMERIC(p, s)`, `JSONB()`, `UUID(as_uuid=True)`, `ARRAY(TEXT())` and so on;
- uses `autoincrement=True` on surrogate primary keys;
- ends its class name in `Orm`, such as `JobOrm`;
- marks every relationship `viewonly=True`, unless writing through the relationship is explicitly required;
- extends the project's shared declarative base, not SQLAlchemy's `DeclarativeBase` directly.

Further rules:

- **ENUM types.** Define PostgreSQL `ENUM` types as module-level variables with `sqlalchemy.dialects.postgresql.ENUM`. Pass `create_type=False` when a migration already creates the type, and register the type on the shared metadata.
- **ENUM columns.** Define a companion `<EnumName>Type` class whose `__class_getitem__` returns the ENUM instance.
- **Junction tables.** Define association tables without a natural primary key with `sqlalchemy.Table` directly, not as a class.
- **Foreign keys.** Every foreign key states an `ondelete` strategy, such as `"CASCADE"`, `"RESTRICT"` or `"SET NULL"`.
- **Database-side defaults.** Use `server_default`, such as `text("(now() AT TIME ZONE 'UTC'::text)")`, `text("false")` or `text("uuid_generate_v4()")`.
- **Shared constraint values.** Module-level private constants, such as `_max_email_length`, may hold constraint values that several columns share.

## Alembic

- **Migrations.** Every schema change comes with an Alembic migration. Never apply DDL by hand.
- **Applied migrations.** Never edit a migration that has been applied to any environment. Create a new revision instead.
- **New revisions.** Create one with `uv run alembic revision -m "<description>"`.
- **Autogenerated migrations.** Review them before committing. Alembic can miss ENUM changes, index changes and custom DDL.
